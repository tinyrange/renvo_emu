01

Charter and meaning of “full”

Target outcome. Unmodified, pinned ESP-IDF examples initialize and use every radio family present on each chip, while a project-owned bare-metal stack can drive the same hardware boundary without linking any Espressif radio code. Transmit, receive, filtering, security, timers, DMA/shared-memory paths, interrupts, power/reset, coexistence, and failure modes produce deterministic, machine-readable evidence.

In scope
  • Complete documented register contracts, including reset values, masks, access modes, reserved holes, and side effects.
  • Firmware-visible ROM calls, PHY initialization/calibration state, modem clocks, sleep, wake, and reset sequencing.
  • A vendor-independent MMIO, DMA, shared-memory and interrupt contract sufficient to implement a complete custom stack from scratch.
  • Packet-level Wi-Fi, BLE, and 802.15.4 behavior sufficient for controller/MAC workflows and protocol peers.
  • Deterministic RF arbitration, loss, collision, CCA, RSSI/LQI, noise, replay, capture, and coexistence.
  • Explicit host adapters for virtual peers, PCAP, browser/WASI, TAP or sockets; disabled unless requested.
Fidelity boundary
  • No claim of analog RF waveform, antenna, multipath, oscillator, or silicon-cycle accuracy.
  • No uncontrolled access to the host network, Bluetooth controller, or wireless hardware.
  • No undocumented “always succeeds” fast paths in acceptance tests.
  • Protocol stacks remain guest firmware, whether supplied by ESP-IDF or implemented independently; Renvo models the hardware/controller boundary.
  • Unsupported silicon features fail explicitly and remain listed until implemented.

03

Clean-room and source-license policy

Hard stop: do not open, read, copy, summarize, or derive implementation details from GPL, LGPL, AGPL, SSPL, source-available, unknown-license, leaked, or unlawfully published source. A useful-looking repository is not an exception.

Allowlist

Primary sources

  • Espressif datasheets, TRMs, programming guides and errata.
  • ESP-IDF files whose exact revision has an explicit permissive SPDX identifier.
  • IEEE specifications available under terms suitable for factual interoperability work.
  • Original black-box probes and traces captured on hardware we are authorized to test.
Pre-read gate

Verify before inspection

  1. Record repository, tag/commit, path, URL and SHA-256.
  2. Verify repository license and per-file SPDX header.
  3. Allow only Apache-2.0, MIT, BSD-2/3-Clause or ISC by default.
  4. Quarantine absent, conflicting or unfamiliar licenses for explicit review.
Implementation rule

Facts, not transplantation

  • Write original Rust from behavioral facts, recovered ABIs and register contracts.
  • Disassemble and analyze only object code whose exact artifact is covered by an approved permissive license and immutable hash.
  • Use permissively licensed vendor binaries to recover calling conventions, state layouts, dispatch tables, register accesses and observable algorithms; do not transplant executable code.
  • Keep a checked source ledger beside qualification evidence.

ESP-IDF v6.0.2 is Apache-2.0 at the repository root, but that does not waive per-file review or third-party exceptions. The research tooling must reject a candidate before exposing its contents when its license is missing or outside the allowlist.

Approved object-form reference: Espressif's esp32-wifi-lib repository explicitly publishes its precompiled RF libraries as Apache-2.0 “Object” form. Pin the exact bb69e7e… submodule revision used by ESP-IDF v6.0.2. Its archives may be disassembled to recover factual ABIs, dispatch tables, state layouts, algorithms and hardware accesses. Implementation remains original Rust and project-owned tests; no vendor machine code is copied into the emulator.

Approved PHY reference: Espressif's esp-phy-lib repository is also Apache-2.0 object form. Pin the exact 59c1234… submodule revision used by ESP-IDF v6.0.2 and hash the C6 and S3 libphy.a archives independently. Disassembly is an offline source of register protocols and calibration algorithms only; runtime behavior remains register-driven LLE.

Mask-ROM execution reference: Espressif's esp-rom-elfs releases publish chip- and revision-specific ROM ELF object files under Apache-2.0. Pin release 20260528 and its vendor checksum. Renvo loads the ROM sections and executes their instructions. Symbols are permitted only as offline disassembly labels: the runtime image discards them, and no symbol name or address may select emulator behavior.

Shared crate

remu-radio

Own protocol-neutral time, spectrum, frames, nodes, seeded channel effects, arbitration and artifacts. It must not depend on C6/S3 machine types or host networking.

  • RadioMedium, RadioNodeId, RfRequest, RfGrant
  • frequency/channel, start/end tick, power, sensitivity and modulation metadata
  • stable event ordering by tick, priority, node and insertion sequence
  • snapshot/replay with configuration and seed hashes
Device models

remu-devices

Own reusable protocol engines and exact register banks. Registers schedule architectural events rather than directly calling host adapters.

  • Wi-Fi MAC/BB/RX/FE state
  • BLE link-layer controller, timer and security state
  • 802.15.4 MAC, filters, CSMA-CA, timer, ACK and AES-CCM state
  • coexistence arbiter and modem clock/power controllers
Machine coupling

remu-machines

Map chip-specific addresses, shared memories and interrupt sources; bind radio nodes to the machine scheduler; expose handles without leaking host I/O into devices.

User boundary

CLI · Rust · JavaScript

Configure isolated virtual media, inject peers/frames, choose a deterministic impairment profile, attach an explicit external adapter, and collect packets/arbitration events.

08

Deterministic RF and coexistence contract

Medium model

Packet airtime, not analog samples

Each transmission reserves a channel interval with protocol, PHY/rate, bytes, TX power and sender position/profile. Receivers evaluate overlap, sensitivity, capture threshold and configured impairment at deterministic event boundaries.

  • Default medium is ideal, isolated and seed-stable.
  • Collision is derived from overlapping airtime, channel width and capture rules.
  • Loss/noise profiles use a named algorithm version plus explicit seed.
  • CCA/ED/RSSI/LQI derive from the same event set seen by receivers.
Coexistence

One RF owner per chip

Wi-Fi, BLE and 802.15.4 submit timestamped requests to a chip-local arbiter. The arbiter grants, delays, preempts or denies access using protocol state, programmed priority and repeatable time slices.

  • Every decision emits request, contenders, winner and reason.
  • Dynamic BLE advertising priority and Wi-Fi state-dependent periods are explicit policy inputs.
  • Resets and power transitions cancel pending grants deterministically.
  • Cross-protocol tests compare event streams and digest across repeated runs.

Ordering: machine event → clock/power eligibility → coexistence decision → medium submission → receiver outcome → DMA/register update → interrupt assertion. Ties resolve by stable node ID and insertion sequence, never thread scheduling or wall-clock time.

Reverse engineering and qualification ladder

Probe A

Static contract extraction

Generate register inventories from license-approved headers: offsets, reset values, access modes, masks, aliases and reserved holes. Diff C6/S3, silicon revisions and the pinned IDF version.

Probe B

Original bare-metal register probes

Compile small project-owned programs with pinned official toolchains. On authorized hardware, record reset reads, writable masks, strobe behavior, timing-independent state transitions and interrupt causes. Never copy vendor implementation code.

Probe C

ESP-IDF initialization checkpoints

Run unmodified examples with project-owned logging hooks at public API/event boundaries. Establish the ROM calls, MMIO pages, shared-memory ranges, DMA ownership changes and interrupts required to reach “started”.

Probe D

Two-node protocol proofs

Pair two emulated machines or one machine with a scripted peer. Prove successful TX/RX, filtering, retries/ACKs, malformed frames, timeout, collision, loss and reset for each radio family.

Probe E

Coexistence and replay

Drive simultaneous protocol demand, verify programmed priority and denial/preemption, repeat across seeds and schedules, and compare canonical artifacts and trace digests.

Probe F

Vendor application suite

Build pinned, SHA-verified ESP-IDF examples in network-disabled containers, run bounded acceptance endpoints, and publish firmware, toolchain, source-ledger and result hashes.

Probe G

Vendor-independent stack proof

Build project-owned bare-metal C and Rust firmware without Espressif radio libraries. Initialize PHY/MAC state through MMIO and shared memory, exchange frames with scripted peers, service native interrupts, and prove that vendor symbols or API interception are not required.

Delivery order

Phase 0

Provenance, truth tables and failing probes

Add the source-license gate and ledger; pin ESP-IDF/toolchains; resolve address conflicts; land generated inventories and negative/failing acceptance probes before behavior.

Phase 1

Shared RF medium and artifact schema

Land protocol-neutral scheduler integration, node topology, ideal-channel TX/RX, collision/loss model, replay, JSON evidence and isolated host API.

Phase 2

Power, clocks, resets, PHY and coexistence skeleton

Implement C6 MODEM_SYSCON/LPCON split, S3 SYSCON coupling, analog-I²C/ROM calibration state, all radio interrupt routes and arbiter request/grant plumbing.

Phase 3

C6 IEEE 802.15.4 vertical slice

Use the most public register boundary to prove the architecture end to end: full register contract, frames, ACK/CCA/CSMA, security, interrupt, scripted peer and ESP-IDF example.

Phase 4

BLE controller on C6, then S3

Implement common BLE controller state and HCI behavior, bind chip-specific timers/MMIO/shared memory, qualify advertising through encrypted connections and sleep/wake.

Phase 5

Wi-Fi on C6, then S3

Implement common Wi-Fi MAC behavior, chip frontends and BB/NRX/FE initialization surface; qualify scan, STA, SoftAP, ESP-NOW, monitor, security and C6 Wi-Fi 6 paths.

Phase 6

Cross-protocol coexistence

Replace skeleton policy with verified schemes, dynamic priority and external coexistence; qualify the vendor-supported pairwise matrices and use three-protocol C6 traffic as deterministic stress, without inventing a vendor support claim.

Phase 7

Comprehensive hardening

Close every register/inventory gap; add reset/fuzz/metamorphic tests, multi-node stress, WASI coverage, performance budgets, dashboards and explicit remaining physical-fidelity limits.

12

Merge gates and definition of done

GATE 01

License provenance

Every research input has URL, immutable revision, hash and approved license. Automated policy finds no prohibited or unknown source in the research ledger.

GATE 02

Register completeness

Generated coverage accounts for every approved public register: reset, mask, access, reserved holes, aliases and side effects. No catch-all register file hides unknown behavior.

GATE 03

Vendor initialization

Pinned unmodified ESP-IDF examples initialize each supported radio family without host shortcuts, unbounded loops or weakening existing startup behavior.

GATE 04

Behavior and failures

TX/RX, interrupts, reset, timeout, filtering, collision, loss, malformed input, queue exhaustion and security failure are deterministic and tested for each applicable protocol.

GATE 05

Coexistence

S3 passes the documented Wi-Fi/BLE scenarios. C6 matches the documented pairwise support matrix—including explicit unsupported cases—and handles three-way stress with observable, repeatable arbitration.

GATE 06

Isolation and replay

No test or default run accesses a real network. Captured inputs reproduce byte-identical packet/arbitration artifacts and stable trace digests.

GATE 07

Regression and performance

All existing non-radio, board, vendor-toolchain, native and WASI suites stay green. Radio-disabled runs remain behaviorally identical and within an agreed overhead budget.

GATE 08

Support claim

Documentation and dashboards enumerate functional coverage and physical-fidelity limits. Issue #338 closes only when no applicable radio peripheral or acceptance item remains unaccounted for.

GATE 09

Real mask-ROM images

ESP32-C6 rev0 and ESP32-S3 rev0 native boot and radio-capable execution require their respective pinned mask-ROM images from Espressif's Apache-2.0 esp-rom-elfs release. Qualification verifies both ROM digests, maps the real ROMs as immutable guest memory, executes the relevant ROM ranges, and forbids functional-ROM or symbol-based dispatch from replacing them. Direct CPU/compiler ELF harnesses that neither boot a native image nor exercise radio remain a lightweight exception. Focused freestanding firmware remains useful for testing low-level MMIO, DMA, shared-memory and interrupt contracts, but it is not required to duplicate every behavior exercised by vendor firmware.
